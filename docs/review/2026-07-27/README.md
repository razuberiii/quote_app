# Rubusoo 全功能交互验收

这份成果用于验收“用户从哪里进入、页面负责什么、点击后得到什么”，不只是检查页面是否能够打开。

## 建议验收顺序

1. 先打开 [`index.html`](index.html)。它把 46 个页面、状态和交付物按顺序放在同一份可视化目录中。
2. 再查看 [`INDEX.md`](INDEX.md)。它逐项列出入口、页面职责、主要操作和结果。
3. 最后打开 `exports/` 中的三份真实导出文件，检查客户最终收到的内容。

## 完整销售流程

1. **建立基础资料**：从“AI 导入”进入公司资料与商品目录导入；识别结果需要核对后才写入正式资料。
2. **创建询盘**：粘贴邮件或聊天、上传客户文件，保存原文并生成当前需求。
3. **持续沟通**：后续客户消息继续追加到同一询盘；页面显示已确认、缺失、冲突和建议追问。
4. **创建并编辑报价**：从询盘生成报价草稿；编辑器优先指出价格、运费、贸易条款等发布阻塞项。
5. **客户预览**：销售确认客户将看到的商品、条款、总价和语言。
6. **发布正式版本**：发布后生成不可变版本，后续修改生成新版本，不覆盖客户已经看过的内容。
7. **交付**：版本页可复制客户链接、下载 PDF、下载 Excel 或记录发送。
8. **客户反馈**：客户可以提问、要求修改或接受报价；反馈回到对应版本。
9. **新版本**：销售核对变化并应用到草稿，再发布下一版本。

## 目录

- `screenshots/`：46 张页面、交互状态和交付物预览。
- `contact-sheets/`：按公开入口、报价流程、客户与设置分组的快速总览。
- `exports/quote-v2.pdf`：销售端导出的正式 PDF。
- `exports/quote-v2.xlsx`：销售端导出的正式 Excel。
- `exports/buyer-room-quote-v2.pdf`：客户公开页面下载的 PDF。
- `manifest.json`：截图名称、实际路径和页面说明的结构化清单。

所有业务数据均为隔离环境中的虚构数据。
