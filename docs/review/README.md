# Rubusoo 新用户完整指南

[观看完整讲解录像（约 1 分 51 秒）](./rubusoo-complete-sales-guide.webm)

这份指南说明销售如何把客户询盘整理成可预览、可发布、可追踪版本的正式报价。录像使用虚构账号和业务数据，所有页面均来自线上环境。

## 一分钟理解产品

Rubusoo 管理的不是一张孤立的 PDF，而是一份持续更新的报价记录：

```text
建立公司资料和商品库
→ 导入客户询盘
→ 持续追加客户沟通
→ 核对当前需求
→ 创建报价草稿
→ 补齐价格、运费和商务条款
→ 预览客户页面
→ 发布正式版本
→ 发送客户链接或下载 PDF / Excel
→ 客户要求修改时创建下一版本
```

销售负责提供沟通原文并确认关键商务数据；系统负责整理变化、保留依据、判断下一步和维护版本。

## 1. 首次设置

### 公司资料

进入 `设置 → 公司`，确认以下信息：

- 对外公司名称与法定名称
- 商务邮箱、电话、网站和地址
- 默认币种、报价有效期、贸易条款和付款条款
- Logo、品牌色及公司文件

已有公司简介或资质文件时，可进入 `AI 导入 → 公司资料与资质`。系统先生成候选资料，确认后才写入公司设置。

### 客户文件语言

进入 `设置 → 文档设计` 设置默认外观。销售后台语言和客户文件语言互不影响：

- 销售可以使用中文后台。
- 每份报价可单独选择 English、简体中文或 Español。
- 客户页面、PDF 和 Excel使用该报价选择的客户语言。

首次使用推荐保留标准版式和默认信息密度，只调整 Logo、品牌色和客户语言。

## 2. 建立商品库

进入 `商品库` 手工新增商品，或通过 `AI 导入 → 商品目录与价格表` 上传 CSV、XLSX、PDF 或图片。

建议保存：

- SKU、商品名称与型号
- 规格、单位、包装和交期
- 参考价格及币种
- 产品图片和客户文件

导入结果不会直接写入商品库。高置信匹配可以保持选中，销售主要处理冲突、重复商品和识别不完整的字段。一次性商品也可以只用于当前报价，不必写入商品库。

## 3. 导入第一封询盘

进入 `AI 导入 → 客户询盘与旧报价`，粘贴整封邮件、聊天记录，或上传客户文件。

系统会整理：

- 买家公司、联系人和联系方式
- 商品、型号、数量和规格
- 币种、目的地、贸易条款和交付要求
- 已确认信息、待确认信息和原文依据

金额、运费、付款条件等关键商务数据没有明确来源时保持待确认，不由系统猜测。

## 4. 客户反复沟通时怎么处理

销售不需要逐句提交，也不需要判断“什么时候该分析”。

在同一份询盘的 `询盘记录 → 添加一条沟通` 中：

1. 一封新邮件可以整封粘贴。
2. 连续聊天可以按一轮沟通合并后一次粘贴。
3. 电话或会议结束后，可追加一段通话纪要。
4. 选择客户回复、销售发出或内部记录，并注明来源渠道。

每次追加后，系统自动比较前后内容：

- 普通补充直接合并到当前需求。
- 修改数量、型号、价格、目的地或贸易条款时标记变化。
- 新旧说法冲突或识别置信度较低时要求销售确认。
- 所有原始消息保持在时间线中，不会被最新结果覆盖。

例如客户先要 5 台，之后改为 8 台并要求分批交付，系统应展示：

```text
数量：5 → 8
交付：一次交付 → 分两批交付
影响：商品金额、运费、交期和报价总额需要重新核算
```

## 5. 什么时候创建报价

页面把缺项分成两类：

- `创建草稿前必须确认`：客户、币种、商品和数量。
- `发布前必须补齐`：单价、价格来源、运费、运费来源、付款条件和最终总额等。

基础范围明确后即可创建报价草稿，无需等待客户把所有细节一次说完整。

## 6. 完成报价草稿

报价工作台集中处理：

- 商品、数量、单价与价格来源
- 运费、折扣、税费和总额
- Incoterm、付款条件、交期与有效期
- 客户可见描述、附件和接受方式
- 客户查看语言

右侧检查区只列出当前发布阻塞项。保存后先打开客户预览，确认语言、金额、条款和版式。

## 7. 发布和交付

预览无误后发布正式版本。发布完成后，`版本与导出` 页面直接提供：

- `客户页面`：无需客户注册的在线报价。
- `PDF`：适合正式发送、打印和归档。
- `Excel`：适合买方采购、核价和内部流转。
- `发送`：交付当前正式版本。

三个输出来自同一个锁定版本，商品、金额和条款保持一致。录像中的线上验收结果：

| 输出 | 验收结果 |
| --- | --- |
| 客户页面 | HTTP 200，可正常打开 |
| PDF | HTTP 200，`application/pdf` |
| Excel | HTTP 200，标准 XLSX 文件 |

## 8. 客户发布后要求修改

已经发布的 V1 不再被改写：

1. 在当前报价的 `客户动态` 中记录客户反馈或修改请求。
2. 系统显示修改内容及其对应的正式版本。
3. 将确认的变化应用到新草稿。
4. 重新核对受影响的价格、运费和交期。
5. 预览并发布 V2。

V1、V2 及后续版本分别保留客户页面、PDF、Excel和沟通记录，可随时追溯客户当时看到的内容。

## 销售日常只需要记住四件事

1. 客户的新沟通始终追加到同一份询盘或报价。
2. 系统自动分析；销售只确认冲突和关键商务数据。
3. 发布前按检查区补齐阻塞项。
4. 发布后发生修改时创建新版本，不覆盖旧版本。
