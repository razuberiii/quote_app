## 已走通

登录 → 公司资料 → 新建商品 → 导入询盘 → 核对结果 → 创建报价 → 报价编辑 → 英文客户预览 → 发布 V1 → 客户链接 / PDF / Excel。

PDF 实际响应为 `application/pdf`，74,478 bytes，文件头 `%PDF`。Excel 实际响应为 OOXML spreadsheet，7,286 bytes，文件头 `PK`。

## 不顺与问题

1. **公司资料分析没有稳定进入“确认并应用”状态。** 原始资料提交后本轮没有出现可应用结果，是当前最明显的流程中断。
2. **询盘核对页确认过的价格和运费没有带入报价草稿。** 销售进入 Quote Studio 后仍需重新填写单价、价格来源、运费和运费来源；这是重复劳动，也是当前最高优先级的业务缺陷。
3. **询盘解析可能把附件/备件拆成独立商品。** 本轮曾把备用密封套件当成第二个报价项目，销售需要判断它应是规格、赠品还是收费附件。
4. **报价编辑页保存前的右侧摘要是旧值。** 输入运费和价格后，画布总额会更新，但摘要与“阻塞项数量”在保存前仍显示旧状态，容易让销售怀疑输入没有生效。
5. **出现一次 Turbo `Failed to fetch` 控制台错误。** 页面最终可继续，但说明导航/提交链路仍存在偶发网络状态处理问题。
6. **新建商品页仍显示英文原生文件控件。** `Choose Files / No file chosen` 与中文产品界面不统一，且上传区视觉比其余字段更像浏览器默认控件。

## 文案判断

- “开始识别”偏技术动作，建议改为“整理公司资料”。
- “创建报价草稿”偏系统对象，建议改为“开始报价”。
- “金额不会自动猜测”信任边界清楚，建议保留。
- “只核对关键结果”“发布前补齐价格与运费来源”的产品逻辑清晰，应继续强化。
- 发布完成页“V1 已生成，交付文件已就绪”是成熟产品语言，动作入口也连续。

## 总监结论

主流程可完成，发布后的交付体验已经顺；主要摩擦集中在报价创建之前的数据连续性。下一轮应优先修复“询盘核对值没有进入报价”和“公司资料分析无可应用结果”，再处理商品附件归类、保存前摘要实时刷新与原生文件控件。
